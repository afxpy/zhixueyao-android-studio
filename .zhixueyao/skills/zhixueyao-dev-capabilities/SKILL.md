# 止血药 · 工程能力层（进程 / Git / 网络 / 脚本 / 记忆）

这五块是**后补的一整层**。在这之前插件只能「读代码、改代码、编译」——
不能看历史、不能上网、不能算，每开新会话还什么都记不住。
参考项目里这些都是基础配置（agents-universe 有 `git_repo`/`web_fetch`/`code_executor`，
insight-agents 有「沙箱定量计算」，astravia 有内置终端和 memory-mode）。

## 1. `ProcessRunner` —— 所有跑命令的地方都走它

新增工具要跑子进程时**不要自己写 `ProcessBuilder`**，用 `ProcessRunner.run(...)`。
它处理好了三件必踩的事：

### ① 分片等待，不能一次等满超时

```kotlin
// ✗ 用户点「停止」时线程还阻塞在 waitFor(120s) 上，那个按钮等于没用
process.waitFor(timeoutMs, MILLISECONDS)
// ✓ 每 100ms 醒一次看取消标志
while (true) {
    if (process.waitFor(100, MILLISECONDS)) break
    if (cancelFlag?.get() == true) { cancelled = true; killTree(process); break }
    if (System.currentTimeMillis() > deadline) { timedOut = true; killTree(process); break }
}
```

MCP 那边就吃过这个亏（最长等 2 分钟才停得下来）。
**探针实测**：命令本身要跑 15s，取消在 568ms 生效。

### ② stdout / stderr 必须并发读

只读一个流的话，另一个流的缓冲区写满，子进程就卡死在写上了——
经典的「进程等我们读，我们等进程结束」死锁。

### ③ 杀进程要连子孙一起

只 `destroy()` 父进程不够：`git` 会 fork 出 `git-remote-*`，脚本会 fork 别的进程。
先用 `process.descendants()` 收一遍，等 400ms 还活着再 `destroyForcibly()`。
（用户点「停止」却发现还在跑，就是这么来的。）

### ④ 环境变量要显式设

```kotlin
environment()["GIT_TERMINAL_PROMPT"] = "0"   // 否则要密码时**挂在终端上等输入**，我们看不到
environment()["GIT_PAGER"] = "cat"            // 否则 git log 调分页器，同样挂住
environment()["LC_ALL"] = "C.UTF-8"           // 否则中文输出乱码
```

**这三条不设，表现为「命令没反应，最后超时」，而错误信息里什么都看不出来。**

## 2. `git` 工具：只读预设下要**按动作**挡，不能按名字挡

预设过滤是**按工具名**做的，而 `git` 一个名字同时含读和写两种动作。
于是两头不讨好：把 `git` 整个归「写」→ 研究模式看不了历史（损失大）；
整个归「读」→ 研究模式能提交（危险）。

解法是**纵深防御**：
- 名单层面把 `git` 放 `READ_ONLY`（保住研究模式的读历史能力）
- `GitTool.execute` 里**按动作再挡一道**：只读预设 + 写动作 → 明确拒绝

`RunScriptTool` 同理（脚本是任意代码，能读也能改文件）。

**刻意不提供 `push` / `reset --hard` / `clean -fd`**：
前两个会搞乱远程仓库或本地工作区，第三个会删掉未跟踪的文件（那些可能从没提交过，删了就真没了）。
这类操作让用户自己在终端决定。

### diff 要给完整改动，不只是 `--stat`

探针抓出来的：一开始只加了 `--stat`，模型调 `diff` 想看「改了什么」，
却只拿到「哪个文件动了几行」——还得再调一次。
现在两个都给：先 stat 给规模，再 patch 给内容，太长由输出截断兜住。

## 3. `web_fetch`：唯一真正危险的是 SSRF

「让 AI 访问一个 URL」听着无害，但服务端请求伪造是真实攻击面：
`http://169.254.169.254/...` 能读到**云主机的实例元数据**（那里面有临时凭据），
`http://localhost:8080` 能探用户本机的管理接口。

**两条必须做对**：

1. **先解析 DNS，再按 IP 判断**。只比域名字符串会被骗 ——
   `127.0.0.1.nip.io`、`localtest.me` 都会解析到环回地址。
2. **跳转要手动跟，每一跳都重新校验**。302 到内网地址是 SSRF 绕过最常用的手法，
   `HttpClient.Redirect.ALWAYS` 会把这条路直接敞开。

拦的网段：环回、私有（10/8、172.16/12、192.168/16）、链路本地、
**云元数据 169.254.169.254**（单独点名，它是这类攻击最常打的目标）、组播/保留。
放行：公网；用户显式 `allow_private=true` 时也放行内网（他可能就是要查公司内网文档）。

HTML 转文本**不要用正则硬解**：先整块丢掉 `script/style/nav/footer/svg`，
再把换行语义的标签换成真换行，最后解实体、压空白。对文档页足够好，且不会因畸形 HTML 崩掉。

## 4. `run_script`：它的价值是「结果是真的，不是估的」

模型算数不可靠 —— 这是它最容易犯错的地方。
凡是涉及**数数、占比、解析、试正则**的，都该真跑一遍。

- 脚本写到**会话临时目录**（不在用户工程里）
- 只允许标准库（装依赖要联网 + 改用户环境，是另一个量级的授权）
- Python 要加 `-u`（不缓冲 stdout），否则超时被杀时拿不到已打印的内容
- 找 Python 要**逐个探测** `python` / `py` / `python3`：
  Windows 上 `python` 有时是 Microsoft Store 的占位程序（运行它会弹应用商店）

## 5. 记忆：与技能的分工要写清楚，否则两边都写乱

| | 记什么 | 形态 |
|---|---|---|
| **记忆** | 事实：「这个项目用 compose 不用 xml」「用户不喜欢 emoji」 | 一句话 |
| **技能** | 方法：「改 UI 前要对照哪些坑」 | 成体系的步骤 |

判断标准：**「这是一句我能直接照做的话，还是一套要读一遍的流程？」**

设计要点：
- 注入提示词**必须有硬上限**（现在 1500 字符）—— 记忆是常驻的，
  不封顶它会慢慢把提示词吃光（和技能目录同一个问题）
- 超上限时**明确说出还有多少条没显示**，否则模型会以为「本机只有这些」而重复记
- **写入就去重**（同样的事说两遍很常见），这是最低成本的防膨胀手段
- 项目记忆放 `<项目>/.zhixueyao/MEMORY.md`，能随工程提交进仓库
