# 渲染类 bug 的排查方法

这份是一个**方向清单**，不是步骤。渲染 bug 的特点是「代码看着没错、跑起来就是不对」，
所以重点在**怎么缩小范围**。

来源：把 6 个参考项目（astravia / agents-universe / insight-agents / mavis / LumeTerm / kemo-agent）
的 CHANGELOG 与前端约定过了一遍，从中挑出与我们同类的问题。下面每条都标了出处。

## 一、最优先怀疑：**用代理指标代替真实状态**

**这是我们踩得最多、也最难发现的一类。**

### 实例：纯文本长回答「展开后一片空白」

`JEditorPane` 设成 `text/html` 后，**即使没塞过内容，`text` 也是一段百来字符的
HTML 骨架**（`<html><head></head><body>…`）—— 永远非空。

于是这段代码是错的：

```kotlin
// ✗ 「richArea.text 非空」≠「正文是富文本在显示」
richArea.isVisible = !collapsed && richArea.text.isNotBlank()
```

一条**纯文本**长回答（没有 Markdown）：`renderRichText` 判 `looksLikeMarkdown == false`
→ 走 `showPlainBody()`，正文在纯文本层。点「展开全文」时却因为上面那句判断为「是」，
**把纯文本层藏起来、把空的 HTML 层露出来** → 展开之后正文没了。
（折叠时又能看到，因为折叠分支是直接写 `bodyArea.text` 的 —— 所以症状是
「折叠有、展开没有」，很容易被当成「展开逻辑没写完」。）

**修法**：让**做决定的那一步**把结果记下来，后面所有地方用同一个判据：

```kotlin
private var richRendered = false        // renderRichText 里如实置位
...
richArea.isVisible = !collapsed && richRendered
```

### 同一个病根的另外两处（同一次排查里发现的）

| 位置 | 症状 |
|---|---|
| `copyAction(source, ...)` 闭包捕获文本 | 切换版本后**点复制，粘出来是旧版本** |
| 折叠按钮的 `mouseClicked` 闭包捕获 `source` | 切换版本后**点展开，看到旧版本的全文** |

按钮只挂一次（有 `ACTIONS_ADDED` 守卫），而 `replaceContent` 会换正文 ——
**闭包里只留「取当前值的入口」，不要留值本身**。

> astravia 在同类问题上的原话修法是「以正文 `contentKey` 为唯一复原条件」
> （他们的 bug 是：展开状态依赖旧的 `children` 引用，hover 操作栏一重渲染就误重置）。
> 措辞不同，**思路完全一样**。

### kemo-agent 的叫法

他们把这类问题叫「**变量链断裂**」：CSS 变量引用了只在某个容器类上定义的别名，
而那个类从未挂到 DOM 上 → `var(--xxx)` 解析为空 → **整条声明失效**
（注意：不是回退到默认值，是整条作废）。

他们给的排查顺序可以直接搬过来：
1. 搜该类是否**真的被使用**（出现 0 次即命中本问题）
2. 搜变量的定义处与引用处**数量是否匹配**
3. 全仓扫描变量名是否**根本不存在**（近似名混淆也常见）
4. 容器支持 `className` 透传就补上挂载，一次性恢复全部引用

## 二、症状 → 先查什么

| 症状 | 先查 |
|---|---|
| **消失了 / 空白** | 是不是被父容器裁掉（`overflow`）、高度算成 0、或可见性用的是祖先不可见的层 |
| **折叠有、展开没有** | 见上面第一节（代理指标） |
| **圆角被切直 / 阴影变方** | 卡片与外层**尺寸齐边** + 外层 `overflow: hidden`。用 `getBoundingClientRect()` 量：两边底边坐标**完全重合**即为齐边 |
| **多出来一条** | 先确认是不是滚动条，再动样式（kemo 的记录：`::-webkit-scrollbar` 之外还要管 `::-webkit-scrollbar-button` 与 `scrollbar-gutter`） |
| **抖动 / 跳动** | 高度在变。查：首帧有没有占位、量高期间有没有锁 `minHeight`、有没有东西「挂载后再纠正」 |
| **闪烁** | 整块被重建，而不是增量更新（astravia：`components` 映射失效 → 自定义节点**整树 remount** → 入场动画对已有文本**整段重播**） |
| **重复渲染同一项** | 去重缺失 + **列表 key 不稳**（astravia 把去重抽成纯函数 `dedupeConnections`，**id 优先、name 兜底**，并把渲染 key 从可能为空的 `id` 换成稳定的 `name`） |

## 三、布局高度：宁可多留，不可少算

### WrapLayout 那次（我们自己的教训）
标准 `FlowLayout` 折行时用 `target.getWidth()`，而**首次布局时宽度还是 0**
→ 按「全部一行」算高度 → 第二排被裁在可视区外。
原则：**宁可多折几行，也不要少算一行（内容会直接消失）。**

### astravia 的同类
- 多行输入退格时 MessageList 抖动：量高期间**锁定输入区父级的 `minHeight`**，
  并在视口尺寸变化且需要贴底时**立即贴底**（不要靠动画追回来）
- 新会话引导词区高度抖动：**固定槽位高度** + 单条单行 `truncate`
- 内容异步出现时布局抖动：**首帧即占位**（只做 `opacity` 入场）、资源一次落盘、
  加载中**预留高度**
- 底部留白用**显式的 spacer 行**，不能只靠 `padding-bottom` ——
  内部自然高度超过可视区时，溢出子项会绘制到父级 padding 区，
  只有处于正常布局流末端的 spacer 才能稳定隔开

### kemo 的同类
模块面板：**外层宿主负责最高高度与滚动**，内部用 Grid；
想要固定列就会和宿主打架。

## 四、流式渲染

### 落尾定时器必须有（我们已有）
只按时间戳丢帧的话，**最后一片可能永远不落地**，正文停在半句话上。

### 节流缓冲不能在有内容的那条路径上被清掉
agents-universe 的记录：`finish_run` 加 `replace_snapshot`，
**只让正常结束路径清掉节流快照** —— 因为 abort / 兜底路径常常是文本仅存的一份。
我们的对应设计：`textBuffer` 是权威副本（每次分片立刻落），
节流只影响**渲染**、不影响**内容** ✓ 保持住这一点。

### 未闭合的结构要显示「未完成」，不要显示原文
kemo 的记录：**流式渲染必须先确认 fence 闭合**。
不能只依赖 `streaming=false`，因为**失败重试快照也会把半截正文收口为静态消息**。
未闭合时应显示占位或未完成状态，**不要把半截标记原样打出来**。

我们对应的实现：`streamBuffer` 会把疑似标记前缀的尾巴（最多 7 字符）
留着等下一片 —— 记得在 `finalize` 时**把它吐出来**，否则流到末尾的那些字会丢。

## 五、两条通用纪律

### 1. 先量，再改
> kemo：「UI 调试先量再改」

不要看一眼就改样式。量出实际数值（尺寸、坐标、颜色、可见性），
**拿数值和预期对**，改完再量一次。

### 2. 改完要验「真的生效」，而不是「源码看起来对」
kemo 的五步验证可以直接搬：
1. 构建
2. **产物核对** —— 在编译产物里搜改后的规则/符号名，确认没有被改写或合并掉
3. **读实际值**（`getComputedStyle()` 的等价物：看控件的实际尺寸/可见性/文本），**不是只看源码**
4. 跑测试
5. 注意缓存

**第 2、3 条对我们特别重要**：Swing 里「属性设了但不生效」的情况很多
（`isOpaque` + `background` 出不来圆角、`RoundedLineBorder` 只画描边、
`BoxLayout` 下 `alignmentX` 被 0.5 居中推偏）——
这些都是**源码看着完全正确、实际没生效**。

## 相关探针

`StaleContentProbe`（6 场景）：切版本后复制/展开/折叠/长度描述是否都用**当前**版本。
关键词是「**闭包不许捕获会变的值**」。
